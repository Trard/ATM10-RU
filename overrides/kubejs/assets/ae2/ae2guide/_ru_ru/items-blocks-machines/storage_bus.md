# Шина хранения

<GameScene zoom="8" background="transparent">
<ImportStructure src="../assets/blocks/storage_bus.snbt" />
</GameScene>

Когда-нибудь хотелось *сохранить* чудовище из сундуков, а не заменить его чем-то разумным? Представляем шину хранения!

Шина хранения превращает прилегающий инвентарь в [сетевое хранилище](../ae2-mechanics/import-export-storage.md).
Она позволяет сети видеть содержимое этого инвентаря, а также помещает и извлекает предметы, исполняя операции
[устройств](../ae2-mechanics/devices.md) с сетевым хранилищем.

Философия AE2 строится на новых механиках, возникающих при взаимодействии функций [устройств](../ae2-mechanics/devices.md),
поэтому шину хранения вовсе не обязательно использовать именно для *хранения*. С помощью
[подсетей](../ae2-mechanics/subnetworks.md) можно сделать одну или несколько шин единственным хранилищем сети и использовать
их как источник либо место назначения при переносе предметов (см. [«Подсеть-трубопровод»](../example-setups/pipe-subnet.md)).

ВАЖНО: крупные оптимизированные инвентари вроде выдвижных ящиков подходят хорошо, но крупные *неоптимизированные* инвентари
со множеством слотов, например колоссальные сундуки, при подключении шин хранения крайне плохо влияют на производительность.

Шины хранения являются [кабельными компонентами](../ae2-mechanics/cable-subparts.md).

## Фильтрация

По умолчанию шина хранит всё. Помещённые в слоты фильтра предметы образуют белый список и разрешают хранение только указанных предметов.

Предметы и жидкости можно перетаскивать в слоты из JEI/REI, даже если у вас их на самом деле нет.

Щёлкните правой кнопкой мыши с ёмкостью для жидкости (например, ведром или резервуаром), чтобы выбрать фильтром саму
жидкость, а не предмет-ёмкость.

## Приоритет

Приоритет задаётся кнопкой с гаечным ключом в правом верхнем углу интерфейса. Поступающие в сеть предметы сначала направляются
в хранилище с наивысшим приоритетом. Если два хранилища имеют одинаковый приоритет, предпочтение отдаётся уже содержащему этот
предмет хранилищу. Отфильтрованные хранилища считаются уже содержащими подходящий под фильтр предмет, если входят в одну группу
приоритета с другими хранилищами. Извлечение начинается с хранилища с самым низким приоритетом. Таким образом, по мере помещения
и извлечения предметов хранилища с высоким приоритетом заполняются, а хранилища с низким — опустошаются.

## Настройки

*   Шину можно разметить (отфильтровать) по текущему содержимому соседнего инвентаря.
*   Можно разрешить или запретить сети видеть предметы в соседнем инвентаре, которые шина не способна извлечь
    (например, шина хранения не может извлечь предметы из центрального входного слота <ItemLink id="inscriber" />).
*   Фильтр шины может применяться и при помещении, и при извлечении либо только при помещении.
*   Шина может работать в обе стороны, только на помещение либо только на извлечение.

## Улучшения

Шина хранения поддерживает следующие [улучшения](upgrade_cards.md):

*   <ItemLink id="capacity_card" /> увеличивает количество слотов фильтра;
*   <ItemLink id="fuzzy_card" /> позволяет учитывать степень повреждения и/или игнорировать NBT предмета при фильтрации;
*   <ItemLink id="inverter_card" /> переключает фильтр с белого списка на чёрный;
*   <ItemLink id="void_card" /> уничтожает помещаемые предметы, если подключённый инвентарь заполнен. Это не даёт фермам
    переполняться, но обязательно внимательно настройте разметку!
